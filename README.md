# SQL 面试练习台

电商增长 / 数据分析岗笔试和面试前，用来把手写 SQL 和口径口头表达练熟的小工具。不是题库网站，题量故意少，每道都要对着空白编辑器能写出来。

**直接开练：** [https://yunzhi1211.github.io/sql-sprint/](https://yunzhi1211.github.io/sql-sprint/)

---

## 给谁用

主用户是：**秋招或提前批，投业务分析、数据分析、用户增长支持** 的同学。岗位日常是看 GMV、拉新拉活、渠道对比、异动下钻，而不是写后端。

尤其适合下面这种情况：

- 本科/硕士不是计算机，会 `SELECT`、`COUNT`、`ORDER BY`，窗口函数和「激活后 N 天」写不利索
- 简历里有 A/B、留存、聚类，但面试官一让当场写 SQL 就卡
- 面试时间只剩几天，需要押**会重复出现的套路**，而不是刷完整个 LeetCode Database

不适合：要系统学数仓/Hive 优化的人；要刷几百道算法 SQL 的人；已经能独立搭看板、随手写漏斗的人。

## 解决什么问题

增长岗 SQL 面试通常不是「难」，是**口径没说清、时间窗写错、分母用错**。本页把真实出现过的题拆成三种练习，对应三种考法：

| 你在面试里会遇到的 | 本页对应模块 | 过关标准 |
|---|---|---|
| 机试 / 笔试限时写查询 | 笔试原题 SQL1–SQL3 | 不看答案，20 分钟内写出且判题通过 |
| 面试官口述：激活 7 日、渠道均值、留存 | 面经分享 SQL4–SQL6 | 能讲清 JOIN、时间窗、paid、无单用户 |
| 概率、p 值、实验周期、相关≠因果 | 选择题 | 能用一句话解释为什么选这个 |

页面布局按笔试站点习惯：**左边选题、中间读题、右边写 SQL 并提交判题**。题面故意不放解题口径，避免还没想就看见答案；卡住再点「提示」，对完再点「题解」。

## 题库怎么编排

### 笔试原题（先练这三道）

来自笔试/机试常见题型，也覆盖增长岗第一轮最爱问的窗口函数。

1. **激活 7 日支付与渠道均值差** — 用户表 JOIN 订单表、激活后时间窗、只计支付、和来源均值做差  
2. **Cohort 留存 month_0–3** — 首单月、月份差、CASE 透视  
3. **DENSE_RANK 销量 Top3** — 并列不跳号、行数可以多于 3

### 面经分享（笔试能写之后再练）

同一套用户/订单数据上的增长指标，对应「拉新拉活、找增长点、日常异动」。

4. **连续活跃天数** — 日期减行号（面试常见追问）  
5. **按来源 7 日转化率与人均 GMV** — 分母是用户不是订单  
6. **激活次日复购 D1** — D1 不是「7 天内任意一天」

### 选择题（穿插，不要攒到最后一天）

概率（箱中取件、疾病检测）、A/B（实验周期、p 值、一类错误、辛普森）、相关与因果、均值/中位数、RANK 区别、留存分母。用来补「SQL 写得出但口答会糊」的缺口。

## 建议怎么用（产品路径）

1. 打开在线页，从 **SQL1** 开始。先只读「题目」和表，自己写，点「自测运行」看结果，再「保存并提交」对照标准答案。  
2. 提交失败先看判题提示（行数、排序、JOIN），仍不会再点「提示」，最后才看「题解」。看完题解必须再默写一遍才算过。  
3. SQL1–3 都能默写后，再做 SQL4–6；选择题每天穿插 2–3 道即可。  
4. 草稿会留在浏览器本地，换题不会丢。换电脑或清缓存会没。

卡住时：**用页面「提示」**，不要指望编辑器里弹出语法。日期加减、窗口平均写在提示分层里。

## 本地怎么跑

需要本机已安装 Python。在项目目录：

```bash
python app.py
```

浏览器会打开 `http://127.0.0.1:8765/`。也可以 `python -m http.server 8765`。

命令行对照自己的 `.sql` 文件：

```bash
python check.py 1 my.sql
python check.py hint 1
```

一周排期见 [PLAN.md](PLAN.md)。

## 刻意不做的事

- 不做成综合题海，避免「刷过但面试写不出」  
- 题面不预置口径，避免还没思考就对照答案  
- 不替代项目深挖：订单归因、A/B 设计仍要按自己的实习/比赛准备口述  

如果你打开后仍看到旧题面，给链接加上 `?v=5` 或强制刷新（Ctrl+F5）。
